# TDMA MAC 层设计（T1 实现：自适应时隙 + 开机自动分配信道）

> 状态：**已实现**（firmware/lib/tdma：TdmaMac + TdmaProto；三端固件已接入）。
> 链路参数依据 [wireless-research.md](wireless-research.md)；帧格式见 [protocol-tdma.md](protocol-tdma.md)。
> 本文件为 MAC 层行为规范，与实现保持一致。

## 1. 超帧结构（每信道独立）

```
┌──────────────────── 超帧 = 30 + 10×N ms ────────────────────┐
│ 信标窗 10ms │ 广播下行窗 10ms │ 设备时隙 0..N-1 (各10ms) │ 注册时隙 10ms │
└──────────────────────────────────────────────────────────────┘
   ↑ 主网关发      ↑ 网关发 1 帧下行      ↑ 每设备 1 时隙        ↑ 新设备/失配设备
     超帧计数/                                                      ALOHA JOIN
     N/mapVer
```

- **N = 该信道活跃设备数**（网关自适应，1..17）→ 超帧 = 30 + 10N ms
- **自适应时延**：N=1 → 超帧 40ms（事件最坏等待 ~40ms）；N=17 → 200ms。
  设备少时超帧自动缩短，时延随之下降。
- 时隙预算依据：10B 帧 @ SF7/BW500k/前导4 空口 ≈ **9.28ms**（前导 2.11 + 载荷
  7.17ms，符号量化），时隙 10ms 留 0.72ms 保护（覆盖晶振漂移 ≤6µs/200ms +
  1km 传播 3.3µs + 收发切换）。

## 2. 信标（10B，type=TF_BEACON，devIdx=0xFF）

| 字段 | 内容 |
| --- | --- |
| payload[0..3] | 超帧计数 uint32 BE |
| payload[4] | `mapVer(3bit) << 5 | N(5bit)` |

设备每超帧收信标：校准相位（`sfStart = rxEnd - 空口时长`）、刷新 N 与 mapVer。

## 3. 开机自动分配信道（设备，含负载均衡）

```
设备上电 → 负载均衡扫描：依次听全部信道（每信道 250ms）收集信标中的 N
  → score = N×100 + 随机0-99，选 score 最小信道（N 最低；N 相同时随机分散，
    并发开机不扎堆同一信道）
  → 在选定信道听信标锁相 → 注册时隙发 JOIN（payload=5B deviceId，随机退避 0-6ms）
  → 网关回 TF_ASSIGN{channelIdx, slot, N, mapVer}
      ├─ slot≠0xFF → 设备锁定 (信道, 时隙)，跳频后按时隙工作
      └─ slot=0xFF（信道满）→ 重新全信道负载均衡扫描（自动避开满信道）
```

- **负载均衡依据**：信标本就广播 N（该信道当前已注册设备数），设备侧零额外开销。
- **平均性**：注册时刻选当前最空信道 → 长期近似均匀分布（如 200 台 / 12 信道 ≈ 16-17 台/信道）；
  运行期不迁移（设备保持注册信道，掉线/新加入由后续注册自然再平衡）。
- 多网关场景：设备只对"能听到的信标"计分 → 覆盖受限时自然选择可及信道。
- 扫描耗时：TDMA_CHANNELS × 250ms + 锁定 250ms（T1 单信道 ~0.5s；12 信道 ~3.3s，
  仅开机/重连一次性）。
- **集中式精确均衡（增强项，T3）**：网关全局注册表按负载把 JOIN 分配到目标信道
  （设备先到任意信道、网关指引跳频）——可做到绝对平均，需跨信道 MAC 重构，暂缓。

## 4. 时隙自适应（网关重排）

| 事件 | 网关动作 |
| --- | --- |
| 新设备 JOIN | 登记 → **reSlot()**：注册序密集重排 slot=0..N-1，mapVer++，逐个下发 TF_ASSIGN（广播窗每超帧 1 帧） |
| 设备心跳超时（30s 无上行） | 移除 → reSlot() 同上 |
| 已知设备重复 JOIN / 心跳 | 仅刷新 lastSeen，**不**重排（避免 mapVer 抖动） |

**设备侧一致性**：
- 设备在 `mapVer 匹配 && slot < N` 时才在自身时隙发射；
- mapVer 失配或 slot≥N → 转入注册时隙补 JOIN（限速），等待新 TF_ASSIGN；
- 因此重排期间不会有两台设备占用同一时隙（旧时隙设备已静默）。

## 5. 时延预算（R4：设备间通讯 <200ms）

| 环节 | 最坏 | 典型 |
| --- | --- | --- |
| 事件 → 自身时隙发射 | 超帧（40~200ms，随 N） | ~超帧/2 |
| 上行 → 网关收到 | 空口 ~10ms | ~10ms |
| 网关 → 服务器（WiFi/WS） | ~20ms | ~5ms |
| 服务器 → 广播窗 → 全体设备 | 下一超帧（≤200ms） | ~超帧/2 |
| **单跳（设备→网络）** | **≤200ms ✓**（设备多时）；设备少时显著更短 | — |

## 6. 网关开机自检与频率自动分配（多射频）

**标准频点栅格**（设备与网关共用，见 TdmaProto.h `TDMA_STD_*`）：
`470.0 + k×2.0MHz，k=0..19`（20 点，覆盖 470~508MHz）。设备扫描全栅格，
只听网关实际使用的频点 → **天然兼容"射频没装满"**。

**开机自检流程**（gateway main.cpp `setup()`）：

```
1. SPI.begin（共享总线 SCLK/MOSI/MISO，NSS 各槽位独立）
2. 槽位探测：对每个已定义槽位（kRfSlots 表），SPI 读 SX1262 版本寄存器 0x0333
   → 版本字节非 0x00/0xFF → 判定存在（空槽位 MISO 悬空读回 0/FF，快速筛除）
3. 以临时频点（470.0）初始化全部检测到的射频
4. 信道质量检测：用射频 0 逐个测量标准栅格 20 个频点——
   RX 模式采样 GW_FREQ_QUAL_SAMPLES×RSSI（间隔 2ms）→ 均值（噪声底）/峰值（信号活动）
5. 质量感知频率分配：均匀散布基线 k_i = round(i×19/(m-1))，理想频点干扰重
   （avg > -95dBm 或 max > -85dBm，阈值可配）→ 在 ±GW_FREQ_SEARCH_WINDOW 栅格
   （±4×2MHz）内选质量最优替代点 → 既保持分散又避开干扰；无干净点则保留并告警
6. 应用最终频率（setFrequency）+ 每射频一个 TdmaMac 实例（myChannel = 栅格索引 k，
   TF_ASSIGN 据此告知设备跳频）
7. 全部失败 → 停机告警；否则按检出数量工作（部分安装即部分信道）
```

**减少干扰**：① 频率均匀散布（间隔 ≥2MHz）；② **开机信道质量检测避开被占用/
噪声高的频点**（RSSI 均值/峰值统计，阈值 `GW_FREQ_AVG_THRESH_DBM`/
`GW_FREQ_MAX_THRESH_DBM` 可配）；③ 合规功率 15dBm + SX1262 邻道抑制度。
自检耗时 ≈ 20 频点 × ~105ms ≈ 2.1s（一次性，可接受）。

**任务栈**：每射频一个 MAC 任务，栈默认 4096 字（`TDMA_TASK_STACK_WORDS` 可配）；
任务创建失败会跳过该射频并告警。12 射频需实测降栈或任务合并（见 gateway-capacity.md）。

**设备侧兼容**：设备扫描全栅格 → 只听到网关实际频点的信标 → 负载均衡注册
（§3）→ 任意"装了几个射频"的网关都无缝工作；网关换射频数/换频点无需重刷设备。

## 7. 多网关（T1 单主；T3 扩展）

- T1：单主网关（信标 + 分配 + 下行）。其余网关（若部署）共听本信道时隙
  上行，`(deviceId, seq)` 去重机制不变；信标主为 gatewayId 最小者（T3 加心跳仲裁）。
- 下行（S/E/R/X/V/W）由主网关在广播窗发射；全局指令（开局/结束/暂停/恢复）
  以广播帧一次送达全体（网关 2s 合并去重），点对点指令按设备逐一发送
  （每超帧 1 帧，时延 ≤ 超帧）。

## 8. 时钟同步与省电

- 设备用 ESP32 40MHz 晶振守时（漂移 10-30ppm → 200ms 内 ≤6µs），每超帧信标校准。
- 设备活动时间 ≈ 信标窗(≤12ms) + 下行窗(≤12ms) + 自身时隙(有帧才 10ms) ≈ 24ms/超帧
  → 接收 duty ≈ 12%，其余时间 radio standby（~1.6mA）。**深睡（SLEEP 0.6µA）留作
  续航优化项**（唤醒需 ~3.5ms，需调整提前量）。

## 10. T1 已知限制（后续 T2/T3 处理）

1. **设备上行速率上限 = 1 帧/超帧**：连续命中/连射场景排队（TX 队列 8 深 ≈ 1.6s@N=17
   突发缓冲，溢出丢新帧）。缓解：F 帧 1s 合并（已实现）、H/D 关键帧优先、必要时
   压缩/合并同类事件。200 设备全速事件场景的吞吐边界见 wireless-research.md §4.1。
2. 单信道单主网关（T3 多信道多射频 + 多网关信标仲裁）。
3. JOIN 只带 5B deviceId，名称/主人关系（头盔 master）未传（服务器侧名称=设备号）。
4. W 帧友军位图假定 `playerId == devIdx`（≤23）；T2 需正确映射。
5. 日志分片 3B/片（上传变慢，低优先级可接受）。
6. 深睡未启用（standby 已省大部分）。
