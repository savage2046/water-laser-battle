# 无线连接方案研究（初步结论：SX126x + 多信道 TDMA）

> 状态：**研究完成，初步决策已定**（SX126x 470MHz LoRa + 多信道 TDMA）。
> 本文件回答三个问题：选哪种无线技术？为什么必须多信道 TDMA？如何满足
> **≤200 设备 / 设备间时延 <200ms / 通讯距离 ≥1km / 单帧固定 10 字节**？
> 配套：现有 ALOHA 紧凑 ASCII 帧协议见 [protocol-915m.md](protocol-915m.md)（过渡版）。

**筛选逻辑**：
1. **1km（R5）**：2.4GHz 全部出局（手持设备 2.4G 实测 50~150m；2.4G LoRa 同样受限于频段传播与 10mW e.i.r.p. 限值）→ 只剩 Sub-G。
2. **200 设备 × <200ms（R3+R4）**：单信道 Sub-G 无论 LoRa/FSK 都放不下（见 §5.1 数学），必须**多信道（FDMA）+ TDMA**，Sub-G 频段 470~510MHz 有 40MHz 带宽，信道资源充裕。
3. **灵敏度/抗干扰**：同样 470MHz 下，LoRa（-131dBm@SF7/500k）比 FSK（-100~-110dBm@250kbps）高 20dB+ 灵敏度，1km 余量天差地别；且 LoRa 抗多径/同频干扰更强 → **LoRa 胜出**。
4. **SX126x vs SX127x**：SX1262 RX 电流 4.6mA（SX1276 为 10.8mA，枪/头盔电池续航关键）、TX 最高 +22dBm（SX1276 为 +20dBm）、QFN24 更小、500kHz 带宽档位、内置 TCXO 支持、阻塞/选择性更好，且是当前 470MHz 模组主流（Ra-01SH / E22-400M22S）→ **SX126x 选定**。

## 4. 容量分析：为什么必须多信道 TDMA（核心）

### 4.1 单信道不可行性（数学）

LoRa 空口时长（符号量化，Semtech AN1200.13）：
- 载荷符号数 = 8 + ⌈(8×PL − 4×SF + 28 + 16) / (4×SF)⌉ × (CR+4)，PL=10B
- 载荷时长 = 载荷符号数 × 2^SF/BW；前导 = (前导符号+4.25) × 2^SF/BW

| 配置 | 数据率 | 前导 | TX 空口(10B) | 时隙(含保护) | 设备时隙/200ms/信道 | **200 设备所需信道** |
| --- | --- | --- | --- | --- | --- | --- |
| SF8/125k（旧固件） | 3.1kbps | 8 | 72.2ms | ~74ms | 2 | **100** ✗ |
| SF7/125k | 5.5kbps | 8 | 41.3ms | ~43ms | 4 | 50 ✗ |
| SF7/250k | 10.9kbps | 8 | 20.6ms | ~22ms | 9 | 23 ✗ |
| SF7/500k 前导8 | 21.9kbps | 8 | 10.3ms | ~11ms | 18 | 12 ✓ |
| **SF7/500k 前导4（采用）** | **21.9kbps** | **4** | **9.28ms** | **10ms** | **17**（另 3 控制槽） | **12** ✓ (204) |
| GFSK 250kbps（对比） | 250kbps | — | ~0.7ms | ~2.2ms | 90 | 3（但 1km ✗） |

> **结论**：单信道 LoRa 在 200ms 内最多提供 2~18 个时隙，200 台设备物理上放不下。
> 唯一出路是 **FDMA + TDMA**：把 470~510MHz 的 40MHz 带宽切为多个信道，
> 每信道独立跑 TDMA 超帧。1km 约束（R5）又排除了 GFSK 高速档
> （250kbps 灵敏度 -102dBm 级，1km 无余量），因此 **LoRa SF7/BW500kHz 前导4 +
> 12 信道** 是同时满足 R3/R4/R5/R6 的组合。
> 实现见 [tdma-mac.md](tdma-mac.md)（T1 已落地）。

### 4.2 推荐链路参数（目标配置）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 频段 | **标准栅格 470.0 ~ 508.0MHz（470 + k×2MHz，20 点）** | 网关开机自检出 M 个射频 → 从栅格均匀取 M 个最分散频点（M=12 → 间隔 ≥2MHz，抗邻道干扰）；设备扫全栅格，兼容"射频没装满" |
| 调制 | LoRa **SF7 / BW500kHz / CR 4:5** | 21.9kbps 净荷；SF7 为远距与速率折中点 |
| 前导 | **4 符号**（10B 帧空口 9.28ms） | 1km 可靠性待实测（§8），必要时回退 6/8 |
| 超帧 | **自适应 30 + 10×N ms**（N=信道活跃设备数 1..17） | N=17 → 200ms（R4 ✓）；设备少时超帧缩短、时延更低 |
| 时隙分配 | **开机自动分配**：扫描信道 → 注册时隙 JOIN → 网关 TF_ASSIGN（信道+时隙+N+mapVer）；网关按注册序密集重排 | 无需静态 devIdx 映射，设备数变化自动调整 |
| 发射功率 | **+15dBm 传导 + 2dBi 天线 ≈ 17dBm e.r.p.（50mW 合规上限）** | 见 §6；保留 22dBm 实验档 |
| 单帧 | **固定 10 字节**（§4.6，已实现） | R6 |

**1km 链路预算（SF7/500k，-131dBm 灵敏度）**：
```
e.r.p. 17dBm + 接收天线 2dBi + 灵敏度 131dB = 150dB 链路预算
1km 自由空间损耗(470MHz) ≈ 86dB → 余量 64dB
实际地面/遮挡/多径衰减 20~35dB → 实测余量仍有 25~40dB ✓
```
即：**合规功率（50mW e.r.p.）下 1km 依然可靠**，无需铤而走险用 22dBm。

### 4.3 超帧结构（自适应 30+10N ms）

```
┌─────────── 超帧 = 30 + 10×N ms（N=活跃设备数 1..17） ───────────┐
│ 信标 10ms │ 广播下行 10ms │ 设备时隙 0..N-1 (各10ms) │ 注册时隙 10ms │
└──────────────────────────────────────────────────────────────────┘
   ↑ 主网关发      ↑ 网关发 1 帧下行      ↑ 每设备 1 时隙        ↑ 新设备/失配
     超帧计数/          （S/E/R/X/V/W）     设备 TX(9.28ms)+保护       ALOHA JOIN
     N/mapVer
```
- **信标**：主网关每超帧起始广播（10B：超帧计数 4B + mapVer/N 1B）；设备校准时钟（§4.8）。
- **广播下行窗**：全员监听，一次广播 = 全体设备同时收到；全局指令（开局/结束/暂停/恢复）
  1 帧送达全部；点对点指令按设备逐帧发送（≤ 超帧）。
- **注册时隙**：新设备/时隙失配设备 ALOHA JOIN（随机退避），网关回 TF_ASSIGN。
- **自适应**：N 由网关按活跃设备数（心跳超时 30s 清理）实时调整，设备每超帧跟随信标
  的 N/mapVer —— 设备少时超帧短，事件最坏等待随之降低（如 N=5 → 80ms）。

### 4.4 开机自动分配信道与时隙（已实现，注册负载均衡）

```
设备上电 → 负载均衡扫描：听全部信道信标，score = N×100 + 随机0-99
  → 选 score 最小信道（N=该信道已注册数，信标广播；N 相同随机分散，并发开机不扎堆）
  → 注册时隙发 JOIN（payload=5B deviceId，随机退避 0-6ms，每 3 超帧一次）
  → 网关回 TF_ASSIGN{channelIdx, slot, N, mapVer}
      ├─ slot≠0xFF → 设备锁定 (信道, 时隙)，按时隙工作
      └─ slot=0xFF（信道满）→ 重新负载均衡扫描（避开满信道）
网关：注册序密集重排 slot=0..N-1，mapVer++；心跳超时（30s）移除设备并重排
设备：mapVer 失配或 slot≥N 时静默并转注册时隙补 JOIN（避免重排期间时隙碰撞）
```

> 设备身份 `DEV_IDX`（0~255）语义不变，仍由 config.h 配置；信道/时隙无需静态规划，
> 全部由网关按运行态分配（动态增减设备自动收敛）。**注册时按各信道负载（信标 N）
> 选最空信道 → 200 台 / 12 信道 ≈ 16-17 台/信道 近似均匀**；运行期不迁移（T3
> 增强项：网关集中式精确均衡）。

### 4.5 多网关漫游（TDMA 下反而更干净）

- **上行**：所有网关共听**全部 12 信道 × 全部时隙**（TDMA 无碰撞，共听即全收，漫游无退化），仍按 `(deviceId, seq)` 服务器去重——**漫游机制与 ALOHA 版完全兼容**。
- **信标**：仅**主网关**（gatewayId 最小者，心跳仲裁）发射；其余网关静默。主网关掉线 → 次主接管（≤ 数超帧）。
- **下行**：仅主网关在广播窗发射（避免多网关同发撞车）；若场地过大导致主网关覆盖不到边缘，按区域增设"下行从网关"（后续版本）。
- **网关硬件**：12 信道并发监听 = **2×SX1302 集中器（16 路解调）** 或 **12×SX1262 多射频板**（见 §7）。

### 4.6 10 字节定长帧（已实现，见 protocol-tdma.md）

```
| devIdx(1B) | type+flags(1B) | seq(2B BE) | payload(5B) | crc8(1B) |
```
- `devIdx`：8 位短设备号（0-255）——沿用，网关学习映射不变；`0xFF`=广播/信标。
- `type+flags`：type 5bit（BEACON/J/H/D/F/B/C/P/T/L/A/W/S/E/R/X/V/ASSIGN 共 19 种）+ flags 3bit（分片首片/续片、头盔标记）。
- `seq`：16 位自增——沿用，去重语义不变。
- `payload(5B)`：事件数据（**完整定义与分片规则见 [protocol-tdma.md](protocol-tdma.md)**）：
  - `HIT`：shooter(2B)+shotSeq+weapon<<4|channel+hp
  - `DEATH`：killer(2B)+shotSeq+channel+energy
  - `TAG`：shooter(2B)+weapon+shotSeq+channel
  - `POS`：3 片（latE6 / lonE6 / yaw+pitch+roll），网关重组
  - `LOG`：part+total+data(3B)
  - `WELCOME`（下行）：3 片（playerId+hp+dmg+ammo / reloadMs+respawnMs+team / scoreToWin+powerLevel+友军位图）
- **已替代** ASCII 帧：现有 [protocol-915m.md](protocol-915m.md)（ALOHA 过渡版）帧语义保留，
  二进制化落地（T2 随 T1 完成）。

### 4.7 时延预算（R4 核算，自适应超帧）

| 环节 | 最坏 | 典型 |
| --- | --- | --- |
| 事件发生 → 自身时隙发射 | 超帧（30+10N ms，N=17 时 200ms） | ~超帧/2 |
| 发射 → 网关收到 | ~10ms | ~10ms |
| 网关 → 服务器（WiFi/WS） | ~20ms | ~5ms |
| 服务器 → 广播窗 → 全体设备 | 下一超帧（≤200ms） | ~超帧/2 |
| **单跳（设备→网络）** | **≤200ms ✓**（N=17）；设备少时显著更短 | — |
| 端到端（设备A事件→设备B收到） | ~400ms（N=17） | ~2×超帧 |

> 命中判定本身走红外直连（本地 <200ms，与无线无关），无线只承担上报与下行控制；
> 若未来要求端到端严格 <200ms，可将超帧缩至 100ms（设备时隙 7/信道 → 约 29 信道，
> 占 29MHz 仍合法）——作为扩展档记录，硬件成本随信道数线性上升。

### 4.8 时钟同步与保护间隔

- 设备用 ESP32 40MHz 晶振守时（漂移 10~30ppm → 200ms 内 ≤6µs），每超帧信标校准一次。
- 保护间隔 0.7ms：覆盖晶振漂移 + 1km 传播时延（~3.3µs）+ 收发切换时间，余量充裕。
- 设备活动时间 ≈ 信标窗 + 下行窗 + 自身时隙（有帧才发）≈ 24ms/超帧 → RX duty ≈ 12%，
  其余 radio standby（~1.6mA）；连续 RX 为 4.6mA。深睡（0.6µA）留作续航优化项。

### 4.9 扩展性

| 场景 | 配置 | 说明 |
| --- | --- | --- |
| 小场地（≤17 设备） | 1 信道（超帧 30+10N ms） | 网关 1×SX1262 + 信标，与现状硬件兼容（T1 已实现） |
| 常规（≤100 设备） | 6 信道 | 网关 6×SX1262 或 1×SX1302（8 路解调） |

## 6. 合规性核查（重要发现）

- 工信部公告 **2019 年第 52 号**《微功率短距离无线电发射设备目录和技术要求》：470~510MHz 微功率设备 **发射功率限值 50mW（e.r.p.，≈17dBm）**，免执照。
- **现有固件 `RADIO_TX_POWER_DBM 22` 为传导功率，配天线后 e.r.p. 达 ~24dBm，超过 50mW 限值** → 存在合规风险。
- **建议**：正式部署时 TX 改为 **+15dBm 传导（+2dBi 天线 = 17dBm e.r.p.）**——§4.2 已证明 15dBm 在 SF7/500k 下 1km 余量充足；22dBm 仅保留为隔离场地/原型实测档并明确标注风险。
- 12 信道占用 470~481MHz（12MHz），处于 40MHz 合法频段内 ✓；多信道同时发射的杂散/带外指标需在样机阶段用频谱仪抽测。
- 参考：[工信部 2019 年第 52 号公告](https://www.miit.gov.cn/zwgk/zcwj/wjfb/gg/art/2020/art_4f2c890530cc4837b2113cf977e249c4.html) ｜ [52 号公告解读（gov.cn）](https://www.gov.cn/zhengce/2019-11/28/content_5456762.htm) ｜ [LoRa 发射功率与 50mW e.r.p. 讨论](http://lora.timeddd.com/archiver/?tid-460.html) ｜ [CN490 频段说明（有人物联网）](https://www.usr.cn/News/998.html)

| 设备端（枪/头盔） | ESP32 + 1×SX1262 模组 | 不变（模组 ¥25-35） | ¥0 |
| 网关射频 | 1×SX1262 | **10×SX1262 多射频板（¥250-350）** 或 **2×SX1302 集中器（¥600-1200）** | 主要新增成本 |
| 网关主控 | ESP32 DevKit | ESP32-S3（IO 多、SPI 快）或树莓派+SX1302 | 视路线 |
| 天线 | SMA 470M | 不变；主网关建议高增益 + 架高 | 少量 |

> 小场地（≤20 设备）网关硬件与现状完全兼容（1×SX1262），多信道网关仅在设备规模增大时按 §4.9 表渐进加装。

## 8. 风险与实测计划

| 风险 | 影响 | 对策/验证 |
| --- | --- | --- |
| 前导 4 符号在 1km 的捕获可靠性 | 密集档掉包 | 样机 A/B 实测（前导 4/6/8 三档对射）；默认用前导 4，必要时回退 |
| 多信道邻道干扰（1MHz 间隔 @500k BW） | 灵敏度恶化 | 频谱仪验证邻道抑制度；必要时间隔加大到 1.5MHz（12 信道占 18MHz，仍合法） |
| 注册时隙 ALOHA 碰撞（多设备同时开机） | 注册延迟 | 随机退避 0-6ms + 每 3 超帧重试，实测收敛时间 |
| 自适应重排（mapVer 变更）期间丢帧 | 个别设备短暂失联 | 失配设备转注册时隙补 JOIN，实测重排收敛 |
| 多网关同时共听 12 信道的硬件复杂度 | 网关成本/开发量 | 先单信道 17 设备原型（T1 已实现）→ 6 信道 → 12 信道渐进 |
| 信标主网关单点故障 | 全网失步 | 次主网关热备切换（≤ 数超帧），T3 实现 |
| 22dBm→15dBm 覆盖回退 | 边缘设备失联 | §4.2 预算显示 1km 余量 25-40dB，实测复核 |
| 与场地其他 470M 设备共存 | 干扰 | 信道规划避开（12 信道内可选频点） |

**原型验证路线**：① 单信道自适应 TDMA（1 网关 1×SX1262 + 枪/盔固件，**T1 代码已就绪**）
→ ② 多信道 100 设备（6×SX1262 或 1×SX1302）→ ③ 12 信道 200 设备（多射频网关）。
每步验证：注册收敛时间、时延（示波器/日志打点，N 变化时实测超帧缩短）、1km 丢包率
（≥95%@15dBm）、多网关漫游去重、电池续航。

## 9. 结论（初步决策记录）

1. **无线技术**：SX126x（SX1262 / SX1268）470MHz LoRa，模组 E22-400M22S / Ra-01SH 级，RadioLib 驱动（现有固件内核不变）。
2. **介质访问**：**多信道 TDMA（FDMA+TDMA）**——单信道 LoRa 数学上不可能容纳 200 设备 × 200ms（§4.1）。
3. **目标参数**：SF7/BW500kHz/CR4:5/前导 4、**标准频点栅格 470+2k MHz（20 点），
   网关自检自动取 M 个最分散频点**（12 信道 → 间隔 ≥2MHz）、
   自适应超帧 30+10N ms（N=信道活跃设备数 1..17，N=17 → 200ms）、**开机自动分配
   信道与时隙**（扫描→JOIN→ASSIGN，网关动态重排，注册负载均衡）、**10 字节定长
   二进制帧**（CRC8）、TX +15dBm 传导（17dBm e.r.p. 合规）。
4. **指标满足**：≤200 设备 ✓（12×17=204）；单跳时延 ≤200ms ✓（设备少时更低）；
   1km ✓（150dB 链路预算）；10B 定长帧 ✓；时隙随设备数自适应 ✓。
5. **合规**：现行 22dBm 超限，正式版降至 15dBm 传导（§6）。

**下一步（待办，见 roadmap.md）**：T1 单信道自适应 TDMA 固件**已实现**（firmware/lib/tdma +
枪/盔/网关三端），待烧录实测：注册收敛、时延随 N 变化、1km 丢包 → T3 多信道网关硬件
（6/12 信道）→ 多网关信标仲裁。
