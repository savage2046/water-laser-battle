## 1. 排查方法：四步固件（都是"最小、单功能、纯 ASCII 输出"）

| 步 | 固件 | 做什么 | 判据 / 结果 |
| --- | --- | --- | --- |
| 1 | `firmware/wire-probe/` | 4 个管脚**不用 SPI**，各输出不同频率方波（NSS=10Hz / SCK=100Hz / MOSI=500Hz / RST=1kHz），硬件定时器分频，示波器直接量 | ✅ 连线/接脚正确（此前 G46 频率"不对"最终定位为 RF 开关/负载相关，非布线错） |
| 2 | `firmware/spi-read/` | 开机复位后读 `0x0320` 版本串 / `0x0740`+`0x0741` 同步字 / `RxGain` / trim / 错误标志 / 随机数 | ✅ `ver="SX1268 V2F 2F02"`、`sync=0x1424`、各复位值全对 → **SPI 四线 + 供电 + 复位正常** |
| 3 | `firmware/lora-tx/` | 配成 LoRa 470.000MHz/SF7/BW500k/CR4-5/私有同步字，每秒发 8 字节 `LRTESTnn`，打印 `TX_DONE` 与**实测空口时间** | ✅ `irq=0x0001 TX_DONE air=8.0xms`（理论 8.00ms） |
| 4 | `firmware/lora-rx/` | 连续接收，每秒打印底噪 RSSI + 收包，按载荷序号算 **PER**；`n` 键扫 460~480MHz | ✅ **19/19 收全、0 CRC、0 包头错**，`rssi=−31dBm / snr=12~13.5dB`，芯片计数与本地计数一致 |

另有 `firmware/spi-probe/`（最早的"面向示波器"版 SPI 接口测试，已被 `spi-read` 取代，
保留其 `b` 键位翻转对照能力）。

**这四步的价值**：把"线通不通 / SPI 读得对不对 / 射频配没配起来 / 空口能不能互通"
拆成四个各自有硬判据的独立环节 —— 任何一步失败都能只看那一步的结论。

### 2.2 【致命】RadioLib 类选错（`SX1262` vs `SX1268`）
RadioLib 用**版本字符串**校验芯片身份：SX1262 类只认 `"SX1261"`、SX1268 类只认 `"SX1268"`。
Ra-01S 是 **SX1268**，用 SX1262 类会重试 10 次后返回 `-2 CHIP_NOT_FOUND`（看着像焊接问题）。
→ `helmet` 已改 `SX1268`（`gun`/`gateway` 早前已改）。

### 2.3 【致命·自研 SPI 驱动必发】三条漏掉的初始化命令
| # | 命令 | 漏发后的现象 | RadioLib 在哪发 |
| --- | --- | --- | --- |
| ① | `SetDio2AsRfSwitchCtrl` `9D 01` | **发射：`TX_DONE` 正常但空口无辐射**；**接收：RSSI 一个字节都不变地卡死**（−88.0dBm，看到的是被隔离的前端）。原因：Ra-01S 收发切换靠 TXEN(脚5)/RXEN(脚11) 的 RF 开关，本板只连 6 根线、没有这两个脚，只能由 DIO2 驱动（表 13-33：RX 时 DIO2=0、TX 时 DIO2=1） | `SX126x::begin()` → `setDio2AsRfSwitch(true)`（`SX126x.cpp:192`） |
| ② | `SetDioIrqParams` `08 03 FF 00 00 00 00 00 00` | `GetIrqStatus()` **恒为 `0x0000`**，轮询永远等不到 `TxDone`/`RxDone`（收敛为"对端在发、本端收不到"）。实测迷惑现象：`irq=0x0000 air=200ms`，但状态字节已报 `0x2C`（bit3:1 = 6 = **Command TX done**）—— 包其实发出去了 | 每次收发前重设：`startReceiveCommon()`（`RX_DONE\|CRC_ERR\|HEADER_ERR`）、`startTransmit()`（`TX_DONE\|TIMEOUT`） |
| ③ | `SetPaConfig` `95 04 07 00 01` + `SetTxParams` `8E 0F 04` | 不配 = **默认低功率 PA（+14dBm 档）** | `begin()` → `setOutputPower(RADIO_TX_POWER_DBM)` |

### 2.4 【重要】SPI 读寄存器偏移错一个字节
SX126x 返回**数据**的命令，命令/地址之后**先有一个 `Status` 字节**，数据在它后面
（手册表 13-25 正文："主机必须在发送两字节的地址后发送一个 NOP…"）→ **数据从第 4 字节起**；
`GetPacketType` 的 packetType 在第 2 字节、`GetDeviceErrors` 的 OpError 在第 2-3 字节。
按"第 3 字节起"读就会整体错位，**特征现象：每条第 1 字节恒为 `0xA2`、版本串内容晚一个字节出现**。
RadioLib 取的是 `buffIn[cmdLen + 1]`（`Module.cpp:402`，其 `widths[STATUS]` 保持默认 `BITS_8`）。

### 2.5 `helmet` 编译不过（5 处）→ 已修
`SX1262` 类不匹配、引脚宏名 `SX_*`→`PIN_SX_*`、`setSPI()`（RadioLib 6.x 已删）、
`setPacketMode()`（只适用 GFSK）、`poll()` 先 `readData` 后 `getPacketLength` 且未先查 IRQ；

### 2.6 网关端换 ESP32-S3 + 接线统一
网关主控由 ESP32 经典款换成 **ESP32-S3**，并**改用与枪端完全相同的接线**：
`NSS=G16 SCK=G42 MOSI=G15 MISO=G41 RST=G46 BUSY=G45 DIO1=G04`
（原网关 MISO=G19 在 S3 上是 **USB D-**，会与 USB 外设打架 → 随统一接线一并消除）。
新增 `checkPinsForS3()`：开机逐脚核对（G19/G20=USB、G26~G32=Flash、G33~G37=PSRAM
一律报 ❌；G0/G3/G45/G46 strapping 报 ⚠）。测试固件随之**去掉单独的网关 env**，两块板都烧 `-e gun-s3`。

### 2.7 正式固件"刷上去没输出"
`ARDUINO_USB_CDC_ON_BOOT=1` 时 `Serial` 走原生 USB-CDC，**主机（监视器）打开之前的打印全被丢弃**；
而 `gun` / `gateway` 的打印**只在 `setup()` 里**、`loop()` 一行串口都没有 → 表现为完全没输出
（测试固件每秒都在打，所以看得见）。已修：
- 开机最多等主机 2.5s；`loop()` 检测到主机接入补打一次 `printSerialReport()`；每 5s 一行心跳；
- 网关 `g_rfCount==0` 的 FATAL 分支从静默 `while(1)` 改成**每 2s 打印一次原因**。

### 2.8 我自己捅的坑（已修）
批量改 README 时用了 PowerShell `Get-Content`/`Set-Content`（PS 5.1 按 GBK 读 UTF-8）→
把 `spi-read`/`lora-tx`/`lora-rx`/`spi-probe` 四个 README 的中文写坏（行尾字符变 `?` + 加了 BOM）。
全仓扫描确认只这 4 个文件中招；"UTF-8→GBK 反演"只能救回大部分（每行行尾仍丢字符），

## 3. 手册结论（可复用，全部有页码出处）

- **`NRESET`（模组第 4 脚）= 输入 + 内部上拉**（表 8-3：所有模式下都是 `IN PU`，
  PU = 典型 **50kΩ** 上拉）—— **没有内部下拉**，悬空即为高（不复位）。
  复位需 **≥50µs 低电平**（一般 100µs）；`VIL_N = 0.2×VBAT` 且 NRESET **参考 VBAT**。
- SPI 为 **Mode 0（CPOL=0/CPHA=0）**、MSB first、最高 **16MHz**；NSS 低开始传输、高时 MISO 高阻。
- 复位后默认 `pktType=FSK`，寄存器为表 12-1 复位值：
  `0x0740=0x14` `0x0741=0x24`（私有网 `0x1424`）`0x08AC=0x94` `0x0911=0x05` `0x0912=0x05`。
- **频率 / SF / 带宽读不回来**（表 12-1 无对应可读寄存器）→ 只能靠"配置后记录 + 扫频"确认。
- 理论空口时间自检（SF7/BW500k/CR4-5/前导4/CRC开）：`PL=8 → 8.00ms`；`PL=10 → 9.28ms`
  （与仓库文档里"10B 帧 ≈9.3ms"一致）。
