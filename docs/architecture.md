# 总体架构（470MHz LoRa 星型组网 + 多网关漫游）

## 1. 系统分层

```
┌────────────────────────────────────────────────────────────┐
│ 表现层    Web 计分控制台（实时计分板 / 对局控制 / 战绩/回放）  │
├────────────────────────────────────────────────────────────┤
│ 服务层    Node.js 对战服务器（中央裁判）                     │
│          对局 · 模式 · 计分 · 去重 · 战绩 · 回放 · 广播      │
├────────────────────────────────────────────────────────────┤
│ 链路层 A  基地台网关 WiFi + WebSocket(JSON)  （远程回传）     │
│ 链路层 B  470MHz LoRa（SX1262 SPI 直驱；ASCII 帧 + ALOHA 多网关共听/广播）  │
│          升级目标：多信道 TDMA（见 docs/wireless-research.md）            │
│ 链路层 C  红外光 940nm 双载波 38kHz/56kHz（枪 ⇄ 枪/头盔，命中判定）  │
│ 链路层 D  网关间 UDP 组播（局域网直连，命中即时感知 <5ms）    │
│ 日志链路   设备 LogBuf 环形缓冲 → 合适时机 470M 分片上传 →     │
│          网关 devLog → 服务器拼接写入 data/logs/*.log         │
├────────────────────────────────────────────────────────────┤
│ 设备层    水弹枪端 ESP32 + SX1262(470M) + 红外收发 + 电机/声光 + OLED │
│          头盔 ESP32 + SX1262(470M) + 红外接收 + GPS + 蜂鸣器      │
│          基地台 ×N ESP32 + SX1262(470M) + WiFi + OLED（远程回传） │
└────────────────────────────────────────────────────────────┘
```

## 2. 三条数据通路

### 2.1 枪 ⇄ 枪（红外直连，命中判定）
扣扳机 → 红外发射管以 38kHz OOK 发送编码帧（射手 16 位 ID + 校验）。
被打中的枪本地解码 → 本地扣血（血量权威在设备端，无线断链不影响判定）。
友军误伤由服务器下发的 `friends` 列表在本地过滤。

### 2.2 枪 ⇄ 网关群（470MHz LoRa，多网关漫游）
- 上行（枪→网关群）：`J` 注册 / `H` 被打中 / `D` 阵亡 / `F` 开火 / `B` 心跳 /
  `C` 夺旗 / `P` 位置；**头盔**上报 `T`（被命中）。
  所有网关同频共听（470.0MHz、SF8/125kHz），**覆盖范围内的每个网关都会收到
  同一帧并各自上报**。
- 下行（网关群→枪）：`W` 欢迎与规则 / `R` 重生 / `S` 对局开始 / `E` 对局结束 /
  `P` 暂停 / `Q` 恢复。服务器指令**广播给所有网关**，所有网关同时发射，
  枪必然收到（重复接收对状态机幂等无害）。
- 事件帧携带 16 位自增序号 `seq`，服务器按 `(deviceId, seq)` 去重，
  多网关重复上报只处理一次。
- 格式为紧凑 ASCII 帧（见 [protocol-915m.md](protocol-915m.md)），每帧 ≤ 64 字节。

**漫游原理**：枪不"连接"任何特定网关——只要处于任意一个网关的覆盖范围内，
上行就能被至少一个网关收到，下行由全网关广播。设备在网关间移动无需任何切换动作。

### 2.3 网关 ⇄ 服务器（WiFi + WebSocket，JSON）
**每条 WebSocket 连接 = 一个网关**。网关注册后上报其听到的设备事件
（`devHello` / `devHit` / `devDeath` / `devFire` / `devHb`，均带 `gatewayId` 与 `deviceId`）。
服务器把设备建模为逻辑实体（按 `deviceId` 标识），下行通过
`{t:"cmd", deviceId, msg}` 广播给所有网关。

### 2.4 网关 ⇄ 网关（局域网 UDP 组播，命中即时感知）
网关收到 470M LoRa 上行事件（H/D/C 等）后，**立即**通过局域网组播转发给所有网关
（本地 <1ms，到达 <5ms），用于本地大屏/语音/影子计分的即时响应，不再等待
远程服务器往返。**服务器仍是唯一计分权威**：只有直接听到 470M 帧的网关才
上报服务器，组播转发的"二手"事件不重复上报，服务器零改动。
详见 [gateway-mesh.md](gateway-mesh.md)。

### 2.5 控制台 ⇄ 服务器（WebSocket，JSON）
控制台：`create` / `start` / `end` / `kick` / `stats`；
服务器广播：`state` 全量快照、`event` 实时事件。协议见 [protocol.md](protocol.md)。

## 3. 多网关漫游设计

```
        覆盖区A          覆盖区B
   ┌─────────────┐    ┌─────────────┐
   │  网关 GW1    │    │  网关 GW2    │
   └──────┬──────┘    └──────┬──────┘
          │ WiFi/WS          │ WiFi/WS
          └─────────┬────────┘
                    ▼
            Node.js 服务器
         · 按 (deviceId, seq) 去重，事件只处理一次
         · 下行 cmd 广播给所有网关
```

| 环节 | 机制 |
| --- | --- |
| 上行共听 | 所有网关同频（470.0MHz 同一信道），枪的帧被覆盖区全部网关收到并上报 |
| 服务器去重 | 每设备维护 16 位 `seq` 窗口，`seq` 前进的事件才处理（回绕安全） |
| 下行广播 | `cmd` 发给所有网关，各网关同时 470M 发射，枪必然收到 |
| 重复无害 | 下行帧对枪状态机幂等（重复 `R`/`S`/`E` 无副作用） |
| 设备身份 | 按 `deviceId`（如 `G0001`）唯一，与所在网关无关 |
| 覆盖判断 | 网关可上报设备信号强度（可选，进阶特性）用于可视化"当前最佳网关" |

## 4. 关键设计决策

| 决策 | 理由 |
| --- | --- |
| 无线主链路用 470MHz LoRa（SX1262） | 470~510MHz 国内合法微功率频段；穿墙远距离、低延迟、无路由器依赖 |
| 无线 MAC 升级目标：**多信道 TDMA**（12 信道×17 时隙=204 设备 / 时延≤200ms / 1km / 10B 定长帧） | 单信道 LoRa 数学上无法容纳 200 设备×200ms；SF7/500k 12 信道为可行组合（方案见 wireless-research.md）；多信道下多网关共听漫游、服务器去重机制不变 |
| 多网关共听 + 服务器去重 | 470M 广播介质天然支持漫游，设备零切换开销 |
| 网关间 UDP 组播直连 | 命中信息局域网内即时流转（<5ms），大屏/语音不等远程服务器 |
| 服务器仍为计分权威 | 组播只做本地快速感知，防作弊与持久化逻辑不变 |
| **一发一杀判定在网关（唯一权威）** | 网关按 `(killer,shotSeq)` 判定 `newKill`（38kHz 远距通道优先 + 组播协调），服务器仅执行结果（kills+1 / upgrade 归属转移），无本地去重判定 |
| 每条 WS = 一个网关 | 设备是逻辑实体，网关可增删不影响设备身份 |
| 470M 链路用紧凑 ASCII 帧 + seq | LoRa 带宽有限；seq 支撑去重 |
| 血量权威在设备端 | 红外命中实时优先，无线断链仍可单机判定 |
| 计分权威在服务器 | 防作弊：去重后的 hit/death 才计分 |
| 帧内容只含射手 ID 不含伤害 | 伤害由模式配置决定，改规则无需重刷固件 |
| 战绩 JSON 文件存储 | 零外部依赖，小规模够用 |
| 回放 JSONL 事件流 | 追加写、易解析，可喂给前端复盘 |

## 5. 时序示例：一次击杀（双网关重叠区）

```
枪A(扳机) ──IR帧(A)──► 枪B(本地解码出A)
枪B 本地扣血至 0 → 阵亡，本地锁扳机
枪B ──H<seq,7>,30──470M──► GW1 ──devHit──► 服务器
枪B ──H<seq,7>,30──470M──► GW2 ──devHit──► 服务器 (seq 相同，服务器丢弃)
枪B ──D<seq,7>──470M──► GW1/GW2 ──devDeath──► 服务器 (只处理一次)
服务器计分 → 广播 event(kill) → 写回放
服务器等待 respawnMs → cmd(respawn) ──► 所有网关 ──R──► 枪B
枪B 满血满弹复活
```
