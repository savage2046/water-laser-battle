# 网关间直连通道（局域网组播，降低命中感知延时）

## 1. 为什么需要

命中判定本身在**枪端本地**完成（红外直连，已是最快）。但"谁击杀了谁"要展示到
本地大屏/语音/影子计分时，默认路径是：

```
枪B → 470M → 网关 → WiFi → 服务器(可能远程/云端) → 广播 → 网关 → 大屏
```

远程服务器往返可达 50~200ms。网关间直连通道让命中信息在**本地局域网**内即时
流转（<5ms），大屏/语音即时响应，不再等远程服务器。

## 2. 设计原则

| 原则 | 说明 |
| --- | --- |
| 服务器仍是唯一计分权威 | 组播通道只做本地快速感知，不替代服务器计分 |
| 只有直接听到 470M 帧的网关才上报服务器 | 组播转发的"二手"事件不再次上报，避免重复 |
| 服务器零改动 | 去重、计分、回放逻辑完全不变 |
| 组播可扩展 | 原型阶段驱动本地打印/LED；可扩展到大屏、语音、影子计分 |

## 3. 数据流

```
枪B 被命中（本地扣血至 0）
  → 上报 470M H/D 帧
  → 覆盖区网关 GW1、GW2 都收到
  → 每个网关立即 UDP 组播转发（源=自己 gatewayId）
  → 所有网关（含 GW3 等未覆盖到该枪的）即时收到（局域网 <5ms）
       → 本地反馈：大屏、语音、LED、影子计分预览
  → 同时 GW1/GW2 照常经 WebSocket 上报服务器（seq 去重，只处理一次）
```

## 4. 组播消息格式

- 组播组：`239.255.43.21:43210`（可配置，见网关 `config.h`）
- 消息为一行 ASCII，`\n` 结尾，长度 ≤ 96 字节：

```
WLB1,<gatewayId>,<kind>,<devIdx>,<seq>[,<p1>[,<p2>]]
```

| kind | payload | 含义 |
| --- | --- | --- |
| `H` | `p1=shooter, p2=hp` | 设备被打中 |
| `D` | `p1=killer` | 设备阵亡 |
| `F` | 无 | 开火 |
| `B` | 无 | 心跳（可选转发） |
| `C` | 无 | 夺旗 |

示例：`WLB1,GW1,H,5,42,7,30`（设备 5 被射手 7 命中，剩 30 HP）
`WLB1,GW2,D,5,43,7`（设备 5 被 7 击杀）

## 5. 接收方行为

1. 校验前缀 `WLB1` 与来源网关（忽略自己的回环包）。
2. 本地即时反馈（原型：打印 + LED 闪烁；可扩展大屏/语音/影子计分）。
3. **不**再次上报服务器（避免与 470M 直接接收重复；服务器去重由
   "直接听到的网关"上报即可）。
4. 可选扩展：维护每设备影子血量/计分，驱动本地大屏。

## 6. 部署注意

- 组播要求所有网关在**同一局域网**且 AP 未开启"客户端隔离（AP isolation）"。
- 服务器可远程（云端），网关间通道纯本地，互不影响。
- 若场地无局域网（纯 470M 无 WiFi 覆盖），此通道自动降级——功能不受影响，
  只是本地大屏无即时数据（仍由服务器广播兜底）。
