# 无改装水弹枪联动方案研究（电流检测扳机 + 断电执行 + ESP-NOW）

> 状态：**研究完成 + 固件原型已实现 + 正式板原理图/PCB 设计完成（待打样实测）**。
> 实现细节见 [trigger-board.md](trigger-board.md)（检测板固件 `firmware/trigger-board/` +
> 枪端集成 `firmware/gun/src/GunEspNow.*`）；正式板工程
> `PCB/triger-sensor.eprj2`（ESP32-C3-WROOM-02-N4 + USB-C + XL1509/AMS1117 电源 + INA226 + UCC27517→20N03）。
> 目标：**不改装水弹枪本体**，实现开火信号检测与音效同步，并在击杀/空弹时
> **物理断电**使水弹无法发射（防作弊硬保证）。
> 关键构想：电池处串联检测板，检测电流周期变化识别"扣扳机→发射"循环；
> 连发电流脉冲周期与射速一致 → 逐发同步音效；检测板与枪端主控用
> **ESP-NOW（用户原话"esp wifi now"）** 连接，确保低延时。

## 1. 目标与硬约束

| # | 需求 | 说明 |
| --- | --- | --- |
| R1 | **不改装水弹枪** | 不拆波箱、不接扳机、不碰枪内电路；检测板仅串联电池回路 |
| R2 | 开火信号 → 枪端 | 检测"扣扳机→发射循环"，通知枪端主控（音效/状态/上报） |
| R3 | 击杀/空弹断电 | 阵亡或弹药归零 → 切断枪电源 → 物理无法发射（防作弊） |
| R4 | 音效同步 | 连发时逐发同步射击音效（电流脉冲周期 = 射速） |
| R5 | 低延迟 | 扣扳机 → 枪端响应 < 20-50ms（感知同步阈值） |
| R6 | 成本 | 增量 ≤ ¥50/把 |

## 2. 系统拓扑（新增检测板，复用现有枪端主控）

```
┌─ 水弹枪本体（不改装）─────────────────────────────┐
│  电池 ──┬── [检测板 ESP32-C3] ──(MOSFET)── 枪电机回路 │
│         │   电流传感 + 断电开关 + ESP-NOW          │
│         └───────────────┬──────────────────────────┘
│  枪端主控 ESP32（现有系统）                         │
│  音效/状态机/470M TDMA   ◄──ESP-NOW(2.4G)── 检测板   │
└──────────────┬─────────────────────────────────────┘
               └── 470M 上报/下行 ──► 网关/服务器（现有）
```

- **检测板**（正式板，`PCB/triger-sensor.eprj2`）：串联在电池与枪之间（电池仓内或电池线上），
  INA226 + 2mΩ 分流电流传感 + UCC27517 栅极驱动 → 20N03 低导通 MOSFET 断电开关 +
  ESP32-C3-WROOM-02-N4 最小系统（原生 USB-C 编程、ESP-NOW 从机）。断电只断枪回路，
  检测板自身从电池直接取电（断电后仍可接收恢复指令）。
- **枪端主控**（现有 `firmware/gun` 的 ESP32）：音效（AudioPlayer）、弹药/血量状态机
  （GunState）、470M TDMA 上报（F/H/D）——全部复用；扳机输入从"微动开关"改为
  "ESP-NOW 开火事件"（可并存，见 §6）。
- **为什么两个设备**：检测板必须贴在电池处（物理位置受限、需要断电开关）；枪端主控
  需要 470M 天线+音效+屏幕（体积大）。两者用 ESP-NOW 无线连接，互不占用物理位置。

## 3. 电流检测原理与可行性（核心）

### 3.1 水弹枪电机电流特征（判定可行的依据）
- 扣扳机 → 波箱直流电机启动 → 电流从 0 阶跃到工作电流，**启动瞬间存在尖峰**
- 单发循环：电机转一圈带动齿轮/活塞 → 电流脉冲持续约 **30~100ms**
- 连发：周期性脉冲，频率 = 射速（水弹枪常见 **600~1200 rpm ≈ 10~20 脉冲/s，
  周期 50~100ms**）——**电流波形直接反映射速**，可逐发同步音效（R4）
- 量级估算：空载 1~3A；启动尖峰 5~15A；堵转 15~25A+；3.7V/7.4V 锂电池
- 参考：水弹/airsoft 直流马达启动电流对电池冲击是常见讨论点（[贴吧讨论](http://jump2.bdimg.com/p/5394114760)），
  锂电池放电平台影响持续射击表现（[淘宝江湖](https://jianghu.taobao.com/detail/47531_85261145)）——
  说明"扳机→电流变化"特征显著，**电流检测可行**

### 3.2 电流传感器选型

| 方案 | 量程 | 接口 | 采样率 | 优点 | 缺点 |
| --- | --- | --- | --- | --- | --- |
| **INA226 + 2~5mΩ 分流** | 可编程（±80mV/分流） | I2C | 连续 ~1kHz+ | 高精度（±0.1% 级）、数字、可编程报警引脚（扳机中断） | 需分流电阻、压降损耗 |
| ACS712/ACS724 霍尔 | ±5/20/30A | 模拟 | 高（1-10kHz ADC） | 隔离、即插即用 | 精度 ±1.5-4%、零点漂移 |
| 采样电阻 + 运放（INA240） | 定制 | 模拟 | 高 | 最便宜、低损耗 | 需运放电路、校准 |

- **推荐 INA226 + 分流电阻**：精度高、I2C 省 IO、**报警引脚可在电流越限时产生中断**
  （扳机检测零轮询延迟）；或用 ACS712-20A 快速原型。
- 采样率需求：识别 10~20Hz 脉冲与 30ms 级单发 → **有效采样 ≥200~500Hz**；
  INA226 连续转换 ~1kHz 满足；模拟方案 ADC 可 1-10kHz（波形更精细，可测启动尖峰）。

### 3.3 扳机/发射识别算法（检测板固件）

```
电流 > 阈值(如 1A) 且持续 > 去抖(10ms)        → 判定"扳机扣动/发射开始"
电流脉冲串（脉冲间隔 < 200ms，周期≈射速）     → 连发；每脉冲 = 1 发
电流回落 < 阈值 持续 > 50ms                   → 发射结束
堵转（持续大电流 > 2s 且无脉冲周期）           → 异常：上报 + 过流保护断电
```

- **逐发同步**（R4）：每个电流脉冲上升沿 → 立即发 ESP-NOW 开火帧 → 枪端播放
  单发射击音效 → 连发音效与真实射速逐发对齐
- **误判规避**：检测板自身耗电需从采样中扣除（空闲基线）；电池充电场景区分
  （充电电流方向/接入路径不同，或充电时枪回路断开）；半扣扳机（电流不足阈值）
- **开机自校准**：不同枪型波箱/电机电流差异大 → 开机学习空闲基线 + 射击电流
  参考值（同网关质量检测思路：先学习再判定）

## 4. 断电执行（R3 防作弊核心）

- **开关**：N-MOS 低端（如 AOT240L RDS(on)≈0.9mΩ / IRLZ44N 逻辑电平）或 P-MOS 高端
  串联电池回路；断开 → **水弹枪完全无电，物理无法发射**（连灯都不亮，不可绕过）
- **触发链路**：
  ```
  本地判定阵亡（红外命中/470M X 帧）或弹药归零
    → 枪端主控 GunState 状态变化
    → ESP-NOW 断电指令（ACK 确认）→ 检测板 MOSFET 断开 → 水弹枪断电
  重生/装弹 → ESP-NOW 恢复指令 → MOSFET 导通
  ```
- **锁存与安全**：断电状态锁存（防重启自愈）；检测板自身独立供电（断电后仍在线，
  可接收恢复指令）；**堵转过流保护**（持续大电流 → 自动断，防烧电机/电池）
- **注意**：若枪有自带电子件（预供弹、自带保护板等），断电会一并切断 → 实测确认
  无副作用；断电后枪内电路复位，重上电可能触发"自检/预供弹"——纳入实测

## 5. ESP-NOW 评估（"esp wifi now"）

### 5.1 特性与实测指标

| 项 | 值 | 说明 |
| --- | --- | --- |
| 频段 | 2.4GHz（与 WiFi 同频共存） | 无路由器、无连接握手 |
| **单跳延迟** | **典型 2~5ms，实测 1~10ms 量级** | 满足 R5（音效同步感知阈值 20-50ms） |
| 距离 | 室内 10~30m；视距 40~100m | 检测板↔枪端主控贴身（<2m），无压力 |
| 速率 | 250kbps（20B payload） | 每发 1 帧 ~10B；连发 20Hz → 40 帧/s，远低于容量 |
| 可靠性 | 广播无 ACK；**用 ACK 模式（esp_now_send 回调）+ 重传** | 断电指令必须确认到达 |
| 参考 | [ESP-NOW 点对点低延迟实战](https://blog.csdn.net/weixin_28933797/article/details/158513967)｜[VANET 时延/丢包实测（MDPI）](https://www.mdpi.com/2227-7080/14/6/344)｜[室内低时延评估](https://science.lpnu.ua/acps/all-volumes-and-issues/volume-11-number-1-2026/performance-evaluation-esp-now-low-latency)｜[距离实测项目](https://github.com/SleXx88/esp32-espnow-range-test) | |

### 5.2 延时预算（扣扳机 → 音效/上报）

```
电流脉冲检测(1~5ms) → ESP-NOW 传输(2~10ms，含重传) → 枪端处理(<1ms)
  ≈ 5~15ms 典型 —— 远小于 20-50ms 同步阈值 ✓
```

### 5.3 绑定与安全
- 检测板 ↔ 枪端主控 **MAC 白名单 + 帧号/时间戳**（防附近其他 ESP-NOW 干扰/伪造）；
  每把枪唯一配对
- ESP-NOW 发即达、无需握手 → 断连自恢复天然；静默超时（如 2s 无心跳）上报异常
- 多把枪同场：2.4G 白名单隔离 + 每对唯一帧格式

### 5.4 与现有 470M 系统的关系（重要边界）
- **ESP-NOW 仅做"检测板↔枪端主控"本地通道**；470M TDMA（上报 F/H/D、下行控制）
  完全不变——两套无线各司其职
- 击杀断电端到端链路：阵亡判定 → 枪端 → ESP-NOW（2-10ms）→ 检测板断电
  **端到端 <50ms 目标**（比 470M 往返更快，断电即时性有保证）
- 2.4G 共存：检测板/枪端主控不开 WiFi（枪端只有 470M，无 WiFi）→ 2.4G 干净；
  若场地网关密集（网关 WiFi 2.4G），实测 ESP-NOW 受影响程度

## 8. 风险与测试计划

| 风险 | 影响 | 对策/验证 |
| --- | --- | --- |
| 电流特征因枪型差异大 | 误判/漏判 | 开机自校准（空闲基线+射击参考值）；**多枪型波形采集** |
| 误判（充电/其他用电/堵转） | 假开火/假断电 | 基线扣除、方向区分、堵转保护+异常上报 |
| ESP-NOW 丢包（2.4G 拥挤） | 音效漏发/断电失败 | ACK 模式+重传；实测同场丢包率 |
| 断电副作用（枪自带电子件复位） | 未知行为 | 实测断电→重上电全流程 |
| 检测板自身功耗 | 电池额外消耗 | ESP32-C3 深睡 + INA226 报警中断唤醒（空闲 µA~mA 级） |
| MOSFET 导通损耗 | 枪性能轻微下降 | 选 RDS(on) <2mΩ；实测射速影响 |

**测试计划**：① 5 种枪型电流波形采集（示波器/日志）→ 识别准确率 ≥99%；
② ESP-NOW 端到端延时统计（1000 次，P95）；③ 断电响应时间（指令→断电 <50ms）；
④ 逐发音效同步主观/波形验证；⑤ 同场 10 把枪互扰测试。

## 9. 结论

1. **可行**：水弹电机"扳机→电流阶跃+脉冲串"特征显著，电流检测识别发射循环成立；
   连发脉冲周期=射速，可逐发同步音效（R4 ✓）。
2. **检测板构成（正式板）**：INA226 + R1=2mΩ（JER2512F3R002）+ UCC27517 栅极驱动 + Q1=20N03
   + ESP32-C3-WROOM-02-N4（USB-C 原生编程）+ XL1509-5.0（11.1V→5V）+ AMS1117-3.3；
   安装于电池回路，**不改枪**（R1 ✓）；成本 +¥30-50（R6 ✓）。
3. **ESP-NOW 达标**：典型 2-5ms 单跳延迟，端到端 5-15ms，满足音效同步与断电即时性
   （R5 ✓）；检测板↔枪端贴身，距离无压力。
4. **防作弊断电是本方案独有价值**：击杀/空弹 → 物理断电 → 水弹无法发射，不可绕过
   （R3 ✓）；470M TDMA 系统零改动复用。
5. **待实测收敛**：电流阈值自校准、ESP-NOW 同场可靠性、断电副作用、MOSFET 损耗。

**下一步**：正式板打样/焊接 → 电源链与 USB-C 烧录验证 → 多枪型电流波形采集 →
识别算法参数校准（`TRIG_CURRENT_A` 等）→ 与 firmware/gun 联调 → 端到端实测
（ESP-NOW 延时 P95、断电响应 <50ms、同场多枪互扰、断电重上电副作用）。
**固件状态**：检测板（`firmware/trigger-board/`）与枪端集成（`GunEspNow`）代码已就绪，
引脚已对齐正式板（IO4/IO5/IO3/IO0）；待硬件实测（编译验证受会话环境限制，接续先 `pio run`）。
