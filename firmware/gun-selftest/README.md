# gun-selftest：枪端主控板（ESP32-S3）硬件体检 + LoRa 联机联调固件

> 版本 **v0.4.0**（新增 T4 LoRa 网关自动连接 + 每秒心跳、T5 940nm/38kHz 光路矫正发射）

专用于 **gun-board.eprj2 / 板子 main**（主控 **LCKFB-ESP32S3R8N8 模组**，
DIP-40 丝印 `Gxx` = `GPIOxx`）的**独立体检 / 联调固件**，与正式
`firmware/gun` 互不干扰：刷入本固件进入体检与联调模式，完成后重新烧录正式
固件即可恢复正常工作。

> 板子刚焊接完，先用本固件**逐项确认硬件能否正常运行**，每加一项检测就在
> 本工程追加一节。**管脚定义以原理图在线读取为准**（见
> `PCB/gun-board/main-ESP32主控-U1管脚定义-在线读取.md`）。
>
> 配套网关侧固件：`firmware/lora-gwtest/`（另一块枪端 PCB 充当 LoRa 网关，
> 与 T4 直接对接联调；它同时给出"网关侧看到的上行 PER/时隙偏移/注册时延"）。

## 1. 硬件与接线

| 检测项 | 引脚 | 说明 |
| --- | --- | --- |
| 板载 LED | GPIO48（丝印 G48） | 灌电流：阳极→3.3V，阴极→限流电阻→GPIO48，**低电平点亮**；模组自带，无需接线 |
| LoRa U2（Ra-01S / SX1268） | CS=G16 SCK=G42 MOSI=G15 MISO=G41 RST=G46 BUSY=G45 **DIO1=G04（2026-09-10 已接线）** | 板上已布（主控页 U2）。DIO1 中断线用于**精确收包到达时刻**（±µs）：信标相位/时隙偏移都以此为准（见 §5）。未接线时写 `-1` 自动退回轮询 |
| ESP-NOW（2.4G，信道 1） | 模组天线 | 对端：检测板（每 1s 发心跳）或 espnow-verify / 另一块本固件板 |

## 2. 编译 / 烧录 / 串口

```bash
cd firmware/gun-selftest

pio run -e esp32s3 -t upload      # 烧录（方式与正式固件 firmware/gun 相同）
pio device monitor -b 115200     # 看启动输出（USB CDC）
```

> 首次编译会自动下载 RadioLib（`^6.5.0`）。本工程也复用仓库共享的
> `firmware/lib/tdma/TdmaProto`（10B 定长帧 + CRC-8），因此 T4 的
> JOIN/HB/ASSIGN 与正式固件**在代码层面就是同一份帧编解码**。

## 2.5 串口输出时机（重要）

本固件的串口打印按 **USB CDC 主机接入**动态输出：

- 上电先 **LED 三闪**（约 0.7s，无串口也能确认程序在跑），随后建立 T4/T5 任务；
- **先开串口监视器再复位/上电**：完整报告立刻可见；
- **先上电、后开监视器**：主机接入瞬间自动补打一次完整报告 + 命令帮助，之后每 5s 一行 `#hb` 心跳；
- 电池单供（无 USB 主机）时打印自动静默、不阻塞，LED 节奏照常；
- 串口走**模组自带 USB-C 的原生 USB（GPIO19/20，USB CDC）**，波特率任意，
  监视器设 115200 即可。若插的是载板电源板的充电口则不是串口。

## 2.6 串口命令（行末回车）

```
h / ?         帮助
i             立即打印完整报告
s             重新扫描 LoRa 网关
j             立刻补发 JOIN（强制重新注册）
k<0-19>       手动锁定频点（跳过扫描，如 k7）
I             暂停 / 恢复 光路矫正发射（测 LoRa 时想排除干扰就用它）
b             立刻发一帧光路矫正信号（单帧，快速确认 LED 是否亮）
c0 / c1 / c2  发射通道：0=近距(G47) 1=远距(G13) 2=两个都发
x             重启
```

## 3. 判定标准

### T1 板载 LED（程序活着 + 联机状态）

| 现象 | 结论 |
| --- | --- |
| 上电**三闪**后进入节奏 | ✅ 代码已启动（不依赖串口） |
| **慢闪**（1s 亮/1s 灭） | ✅ 已连上 LoRa 网关（已获信道+时隙） |
| **中速闪**（260ms） | ⚠️ 射频 OK 但**未连上网关**（扫描/注册中，看串口 T4） |
| **快闪**（120ms） | ❌ 射频初始化 FAIL（看串口 T2 的错误码） |
| 每秒叠加一次**短亮 40ms** | ✅ T5 光路矫正信号正在发射（亮 0.7s / 灭 0.3s） |
| 常亮 / 常灭 / 毫无反应 | 见 §5 |

### T2 LoRa 模块连接（开机自动执行一次）

串口打印 `#RESULT lora=PASS` 或 `#RESULT lora=FAIL (begin=<错误码>)`：

| 输出 | 含义 |
| --- | --- |
| `begin 返回 0` → `#RESULT lora=PASS` | 复位→校准→SPI 状态/寄存器自检全过：U2 在位、六线焊接 OK |
| 打印 `版本寄存器 0x0320 = "SX1262"` | 芯片身份正确（RadioLib `findChip` 同源） |
| 打印 `理论空口(10B) = 9280us` | SF7/BW500k/前导4 的 10 字节帧空口时长（可与实测发射耗时对比） |
| `begin=-2`（`CHIP_NOT_FOUND`） | ⚠️ **先排除类选错**：U2 是 Ra-01S = **SX1268**，而 RadioLib 用 0x0320 版本字符串校验身份（SX1262 类只认 `"SX1261"`、SX1268 类只认 `"SX1268"`）→ 拿错类必然 -2。本固件已**自动依次试 SX1262/SX1268/LLCC68**，报告里会写"已自动试过三个类"，此时才是硬件问题：U2 供电/CS(G16)/BUSY(G45)/RST(G46)/SPI 焊接/U2 贴反。详见 `docs/lora-gateway-test.md` §4.0 |
| `begin=-16`（`SPI_WRITE_FAILED`） | 写读回不一致：MOSI/MISO/SCLK 虚焊错位 |
| `begin=-705/-707` | 命令超时/失败：多半 BUSY(G45) 或 RST(G46) |

### T3 ESP-NOW 自动连接（开机自动执行一次）

算法（`src/EspNowAuto.cpp`）：

1. **开机先连「上次成功连接的地址」**（NVS，key `gun-st/peer`）——每 300ms 单播探测，窗口 3s；
   判定成功 = 收到链路层 ACK 或该 MAC 的任一帧；
2. **3s 未连上** → promiscuous 旁路抓包 1.6s（只统计 ToDS=0/FromDS=0 的直连数据帧），
   按源 MAC 统计平均 RSSI 与帧数 → 逐一带信号最强的探测 → 成功写回 NVS。

| 输出 | 含义 |
| --- | --- |
| `#RESULT espnow=PASS` + peer MAC | ✅ 已连接 |
| `code=-1` | 上次地址 3s 未连上，扫描也没侦听到设备帧 |
| `code=-2` | 扫到候选但逐个探测均无 ACK |
| `code=-3` | 没保存过地址，附近也没有任何设备在信道 1 发帧 |
| `code=-4` | `esp_now_init` 失败（罕见） |

> ESP-NOW 接收回调不带 RSSI（Arduino core 2.0.17），所以"信号最强"靠旁路抓包实现，
> **对端必须真的在发帧**。

### T4 ★ LoRa 网关自动连接 + 每秒心跳（`src/LoRaDev.*`）

流程：

1. 按 `470.0 + k×2.0 MHz` 扫 **20 个标准频点**（每点驻留 250ms，一轮约 5s）找网关信标
   `TF_BEACON`；若在别处已成功过，**优先重试上次的频点**（重连只需 250ms）；
2. 锁相：以**信标空口起点**为超帧基准（与网关同一参考点）；
3. 在**注册时隙**发 `JOIN`（payload = `"G0001"`，带 0~2ms 随机退避）；
   网关回 `TF_ASSIGN`（信道/时隙/N/mapVer）；`slot=0xFF` = 信道满 → 重新扫频；
4. **心跳：每 1000ms 入队一个 `TF_HB`，在自身时隙内发出**（每超帧最多一帧）；
5. 掉线：5s 没听到信标 → 判掉线，回到 1)。

串口输出：

| 输出 | 含义 |
| --- | --- |
| `[T4] 听到网关信标：k=0 (470.0MHz) N=1 rssi=-62 snr=5.25` | ✅ 找到网关并锁相 |
| `[T4] 注册槽发 JOIN（k=0 slot偏移 -120us）` | 已发注册帧 |
| `[T4] 获得分配：k=0 slot=0 N=1 mapVer=3（注册时延 41ms）` | ✅ **自动连接成功**，已获时隙 |
| `#RESULT gateway=PASS (hb=42)` | ✅ 联机成功，已发 42 次心跳 |
| `#RESULT gateway=JOINING` | 已锁信标但还没拿到 ASSIGN（网关是否在跑 GW 模式？） |
| `#RESULT gateway=FAIL` | 没扫到信标（网关没上电/不在标准栅格/太远/天线未接） |

报告里的关键指标：

| 指标 | 正常 | 异常 → 排查 |
| --- | --- | --- |
| 心跳发送间隔 | ≈1000ms（目标值） | 偏大 → 时隙没拿到 / 网关切走 / 光路发射把它挤掉 |
| 时隙对齐偏移 | \|avg\| < 1ms | 抖动大 → 本机定时被抢占（可用 `I` 暂停 T5 对比） |
| 信标 RSSI / SNR | 近距离 −40~−70dBm / >3dB | 偏低 → 天线/距离/功率 |
| 注册时延 | 40~120ms | 长期 JOINING → 网关注册窗裕量不足（见 `docs/lora-gateway-test.md` §4.2） |
| 上帧空口耗时 | ≈9280µs | ≈46000µs → 用到了阻塞 `transmit()`（本固件已规避） |

### T5 ★ 940nm / 38kHz 光路矫正发射（`src/IrAlign.*`）

- **节奏**：每 1000ms 一个周期，**光信号持续 700ms**（亮 0.7s / 灭 0.3s）。
  点亮期间"背靠背"连发编码帧（单帧约 81ms → 一个周期约 8 帧），
  既是"常亮可见"便于目视对准，又能被接收端反复解出完整帧。
- **载波**：半周期 13µs → **38.46kHz**（XL-IRM-V838M3 中心 37.9kHz 带通内）。
- **功率**：**档位 0 = 最低**（近距通道 A/B 均低 = `00` = 0.5×I_nom；
  远距通道档位 0/1 均为近档小电流）。最低功率 → 只在小距离内可解码，
  正好用于近端对光与检查光路。
- **编码**：与正式 `firmware/gun/src/LaserCodec.cpp` **逐位一致**
  （引导码 9ms 载波 + 4.5ms 间隔 + 40bit：`playerId|weapon|team|shotSeq|chk`），
  所以头盔 / 校准靶能把它当成一次**真实命中**解出来（校准靶会蓝闪 3 次）。

| 目视/仪器现象 | 结论 |
| --- | --- |
| 手机摄像头能看到 LED **每秒亮 0.7s** | ✅ 发射驱动链路 + LED 正常 |
| 示波器看 G13/G47：38.46kHz 方波，9ms 引导码 + 40 位脉冲 | ✅ 载波与时序正确 |
| 接收头/校准靶**有反应（解码成功）** | ✅ 光路对准、亮度足够 |
| 接收端无反应 | 距离太远（最低功率档，属预期）/ 光路偏 / 波长或频率不匹配 → 换通道 `c0`/`c1` 单独试，或改用校准靶贴在 LED 正前方 10~30cm |

## 5. 实现要点与踩坑（重要）

1. **DIO1 已接 G04（2026-09-10）→ 收发与到达时刻都靠它**。
   - **收包**：`startReceive()` 把 DIO1 掩码设成 `RX_DONE`，所以上升沿 = 收到包；
     ISR 里记 `micros()` → 到达时刻 **±µs**。T4 的"信标相位"就是
     `到达时刻 − 9.3ms 空口`，时隙偏移也基于它 —— 没接 DIO1 时只能取
     "轮询到包的时刻"（`vTaskDelay(1)` 轮询误差可达 ~1ms），相位会对不准。
   - **发射**：本固件仍用 `startTransmit()` + 轮询 `TX_DONE`（接没接都能跑，
     还能顺带实测空口耗时 ≈9280µs，正好用来反证 DIO1 接好了）。
     `_txWindow` 把发射期间的 DIO1 跳变屏蔽掉，避免被误当收包时刻。
   - **附带收益**：接上 DIO1 后 `firmware/gun/src/RadioLink.cpp` 与
     `TdmaMac::txFrame()` 里的**阻塞 `transmit()` 自动恢复正常**（~9.3ms 返回，
     而不是白等 46ms 才 `TX_TIMEOUT`）—— 见 `docs/lora-gateway-test.md` §4.1。
   - ⚠️ 连带改线：**G04 原来规划给 `IR_RX`（38k 接收头），现已迁到 G14**；
     原 G14 的 940 功率档取消（`PIN_IR_POWER 0xFF`，940 是单档硬件）。
     `firmware/gun/src/config.h` 已同步。
2. **不能用阻塞 `transmit()` 等 DIO1 电平的老写法**（`while(!digitalRead(getIrq()))`）：
   即使 DIO1 接好了，本固件也不走那条路 —— 因为它会阻塞整个 TDMA 时隙窗口。
   接收同理轮询 `RX_DONE/CRC_ERR/HEADER_ERR`，并**严格在 `readData()` 之前
   调用 `getPacketLength()`**（RadioLib 文档要求）。
2. **T4 全程保持连续 RX**（不在窗口间 `standby()`）：任一时刻收到信标都能重新锁相，
   即使被别的任务抢占也不会失锁（正式 `TdmaMac` 是窗口式武装，易受打扰）。
3. **T5 放在 core0（优先级 10），T4 放在 core1（优先级 5）**：38.46kHz 载波半周期
   仅 13µs，任何抢占都会让载波跑偏、接收头带通解不出；两个任务分核互不干扰。
   T5 每个周期只在"灭"的 0.3s 让出 CPU（任务看门狗 5s，安全）。
4. **串口丢输出问题**（沿用 v0.3.0 的修法）：所有打印走 `dsLog()` 且由
   `(bool)Serial` 门控——无主机静默不阻塞；主机接入瞬间补打报告，
   首个 5s 心跳周期再复述一次（绕过 USB CDC 枚举窗口丢帧）。

## 6. 常见问题

### 串口没有任何输出 —— 按顺序排查

1. **看 G48 LED**：
   - **上电三闪 + 之后有节奏地闪** → 程序在跑，问题在串口侧；
   - **完全不闪/常亮** → 程序没跑起来，查供电 3V3、烧录日志、下载模式（按住 BOOT 再复位）。
2. 串口线插**模组自带 USB-C**（原生 USB 口），不是载板/电源板充电口；
3. `pio device list` 确认端口；USB CDC 复位后会**重新枚举**——关掉监视器重开一次；
4. 复位后再看：上电先三闪，接上主机后自动补打完整报告。

### T4 FAIL 排查

| 现象 | 优先排查 |
| --- | --- |
| `gateway=FAIL`（扫不到信标） | 网关板是否在跑 GW 模式（`firmware/lora-gwtest` 的 `m2`）？网关是否在标准栅格频点？距离/天线？ |
| 一直 `JOINING` | 网关是否在正常发信标+收注册槽；网关侧串口是否出现 `JOIN dev=…`；**必要时在网关侧把注册窗裕量调大**（见 `docs/lora-gateway-test.md` §4.2） |
| `JOINING` 后又变 `FAIL` | 信标 5s 没收到 → 掉线重扫（网关重启了？被 `k` 命令换了频点？） |
| 心跳计数不涨 | 时隙没拿到（状态仍是 JOINING）；或网关端没在时隙里收（检查网关报告里的 `dev=` 表） |
| 想看纯链路（排除光路干扰） | 串口发 `I` 暂停 T5，对比心跳间隔/时隙偏移 |

### T5 不亮 / 接收端无反应

| 现象 | 优先排查 |
| --- | --- |
| 手机摄像头完全看不到光 | 通道选对没（`c0` 近距 G47 / `c1` 远距 G13）？LED 极性/焊接？Q1/Q4 MOSFET 焊接？ |
| 亮但接收端解不出 | 距离（最低功率档只在近处有效，先 10~30cm）？光路偏？接收头是否 37.9kHz 带通？ |
| 想更亮 | 改 `config.h` 的 `IR_ALIGN_POWER_LEVEL`（1/2/3 = 1.0/1.5/2.0×I_nom），**注意 940nm 不可直视** |
| 只在近距离可见（符合预期） | 最低功率本就是为"近端对光"设计的 |

## 7. LED（G48）指示汇总

| 模式 | 含义 |
| --- | --- |
| 上电三闪（约 0.7s） | 代码已启动（不依赖串口） |
| 慢闪（1s 亮/1s 灭） | ✅ 已连上 LoRa 网关 |
| 中速闪（260ms） | 射频 OK，未连上网关（扫描/注册中） |
| 快闪（120ms） | 射频初始化 FAIL（T2） |
| 叠加短亮 40ms | T5 光路矫正信号正在发射 |
| 常亮 / 常灭 | 程序未正常启动或 LED 通路异常（查 §6） |
