# gun-selftest：枪端主控板（ESP32-S3）硬件体检固件

专用于 **gun-board.eprj2 / 板子 main**（主控 **LCKFB-ESP32S3R8N8 模组**，
DIP-40 丝印 `Gxx` = `GPIOxx`）的**独立硬件体检固件**，与正式
`firmware/gun` 互不干扰：刷入本固件进入体检模式，体检完成后重新烧录正式
固件即可恢复正常工作。

> 板子刚焊接完，先用本固件**逐项确认硬件能否正常运行**，每加一项检测就在
> 本工程追加一节。**管脚定义以原理图在线读取为准**（见
> `PCB/gun-board/main-ESP32主控-U1管脚定义-在线读取.md`）。

## 1. 硬件与接线

| 检测项 | 引脚 | 说明 |
| --- | --- | --- |
| 板载 LED | GPIO48（丝印 G48） | 灌电流：阳极→3.3V，阴极→限流电阻→GPIO48，**低电平点亮**；模组自带，无需接线 |
| LoRa U2（Ra-01S / SX1268） | CS=G16 SCK=G42 MOSI=G15 MISO=G41 RST=G46 BUSY=G45 | 板上已布（主控页 U2），DIO1 未接（RadioLib 轮询 BUSY） |
| ESP-NOW（2.4G，信道 1） | 模组天线 | 对端：检测板（每 1s 发心跳）或 espnow-verify / 另一块本固件板（需在信道 1 上电收发） |

## 2. 编译 / 烧录 / 串口

```bash
cd firmware/gun-selftest

pio run -e esp32s3 -t upload      # 烧录（方式与正式固件 firmware/gun 相同）
pio device monitor -b 115200     # 看启动输出（USB CDC）
```

> 首次编译会自动下载 RadioLib（版本与正式固件一致 `^6.5.0`），需联网一次。

## 2.5 串口输出时机（重要）

本固件的串口打印按 **USB CDC 主机接入**动态输出：

- 上电先 **LED 三闪**（约 0.7s，无串口也能确认程序在跑），随后执行 T2 并进入 LED 节奏；
- **先开串口监视器再复位/上电**：完整报告立刻可见；
- **先上电、后开监视器**：主机接入瞬间自动补打一次完整报告，之后每 5s 一行 `#hb` 心跳；
- 电池单供（无 USB 主机）时打印自动静默、不阻塞，LED 节奏照常——一切正常；
- 串口走**模组自带 USB-C 的原生 USB（GPIO19/20，USB CDC）**，波特率任意（CDC 固定），
  监视器设 115200 即可。若插的是载板电源板的充电口则不是串口。

## 3. 判定标准

### T1 板载 LED（程序活着）

| 现象 | 结论 |
| --- | --- |
| 上电**三闪**后进入节奏 | ✅ 代码已启动（不依赖串口） |
| 之后 G48 LED **每秒闪 1 次**（亮 0.5s / 灭 0.5s） | ✅ T1+T2 全部 PASS |
| 之后**快速闪烁**（约 120ms 亮/灭） | ⚠️ 程序在跑，但 T2 LoRa 连接 **FAIL**（看串口原因） |
| 常亮 / 常灭 / 毫无反应 | 见 §5 |

### T2 LoRa 模块连接（开机自动执行一次）

串口会打印 `#RESULT lora=PASS` 或 `#RESULT lora=FAIL (begin=<错误码>)`：

| 输出 | 含义 |
| --- | --- |
| `begin 返回 0 (RADIOLIB_ERR_NONE)` → `#RESULT lora=PASS` | 复位→校准→SPI 状态/寄存器自检全过：U2 在位、六线焊接 OK |
| `#RESULT lora=FAIL (begin=-2)` | `CHIP_NOT_FOUND`：芯片无应答（CS/MISO/BUSY/供电） |
| `#RESULT lora=FAIL (begin=-16)` | `SPI_WRITE_FAILED`：写读回读不一致（MOSI/MISO/SCLK 虚焊错位） |
| `#RESULT lora=FAIL (begin=-705/-707)` | 命令超时/失败：多半 BUSY(G45) 或 RST(G46) 有问题 |
| 附带 `RF 空闲底噪 RSSI = xx dBm` | 接收态底噪参考（通常约 -90~-115dBm；明显偏高提示干扰/天线异常，仅参考不判 FAIL） |

### T3 ESP-NOW 自动连接（开机自动执行一次）

算法（`src/EspNowAuto.cpp`）：

1. **开机先连「上次成功连接的地址」**（NVS 持久化，key `gun-st/peer`）——
   加入 peer 后每 300ms 单播探测帧，窗口 3s；
   判定成功 = 收到该 MAC 的**链路层 ACK**（`ESP_NOW_SEND_SUCCESS`）或收到它的任一帧；
2. **3s 未连上** → 进入扫描：promiscuous 旁路抓包 1.6s（只统计 ToDS=0/FromDS=0 的
   直连数据帧 = ESP-NOW 设备互发帧），按**源 MAC 统计平均 RSSI 与帧数**；
   候选按"平均 RSSI 高、帧数多"排序 → **逐一带信号最强的探测**（各 ≤900ms），
   成功即把该地址写回 NVS（下次开机优先连它）。

串口输出：

| 输出 | 含义 |
| --- | --- |
| `#RESULT espnow=PASS` + peer MAC（命中“上次地址”或注明“扫描候选 N 个”） | ✅ 已连接 |
| `code=-1` | 上次地址 3s 未连上，扫描也未侦听到设备帧（对端没上电/不在信道 1/静默） |
| `code=-2` | 扫到候选但逐个探测均无 ACK |
| `code=-3` | 没保存过地址，附近也没有任何设备在信道 1 发 ESP-NOW 帧 |
| `code=-4` | `esp_now_init` 失败（罕见，WiFi 栈问题） |
| 候选列表行 | FAIL 时打印前 5 个候选 MAC/RSSI/帧数，便于判断扫到了谁 |

> 说明：这个 Arduino core（2.0.17）的 ESP-NOW 接收回调不带 RSSI，所以"信号最强"
> 靠旁路抓包实现——**对端必须真的在发帧才量得到**。检测板每 1s 发心跳（单播给枪或
> 广播）所以必能扫到；espnow-verify / 另一块本固件板静默时扫不到，需先让它发帧
> （espnow-verify 收到检测板帧即有流量；或两块自检板互发）。
>
> 测试用命令：串口输入 **`x`** → 清除已保存地址并重启（从头测"扫描选最强"分支）。

## 5. 常见问题

### 串口没有任何输出 —— 按顺序排查

1. **看 G48 LED**：
   - **上电三闪 + 之后有节奏地闪** → 程序在跑，问题在串口侧（见 2/3/4 步）；
   - **完全不闪/常亮** → 程序没跑起来（没烧进/上电失败），查供电 3V3、烧录日志
     （应出现 `Hard resetting via RTS pin...`）、下载模式（按住 BOOT 再复位）。
2. 串口线插**模组自带 USB-C**（原生 USB 口），不是载板/电源板充电口；
   电脑设备管理器应出现串口（ESP32-S3 CDC）。
3. `pio device list` 看端口号，确认 `pio device monitor -b 115200` 用的就是它；
   USB CDC 在复位后会**重新枚举**——如果监视器是复位前打开的，关掉重开一次。
4. 复位后再看：上电先三闪、接上主机后自动补打完整报告并每 5s 打 `#hb`。
   若仍无输出但 LED 正常：换根数据线（不要充电线）/ 换 USB 口 / 检查驱动。

### T1 LED 不闪 / 无反应

- **完全无反应 + 串口无输出**：先量电源——模组 3V3 是否到位；18350/5V 升压是否正常；
  排针/插座是否插紧或虚焊。
- **LED 常亮**：GPIO48 被外部拉低/引脚冲突，先拔载板外设只留模组再试。

### T2 LoRa FAIL 排查

| 现象 | 优先排查 |
| --- | --- |
| `begin=-2`（无应答） | U2 供电 3.3V/GND；CS(G16) 是否连到 U2 NSS；BUSY(G45) 是否连 U2 BUSY；RST(G46) 是否连 U2 RESET；U2 是否贴反/虚焊 |
| `begin=-16`（回读不一致） | MOSI(G15)/MISO(G41)/SCK(G42) 与 U2 对应脚是否错位/虚焊；SPI 线上串阻 |
| `begin=-705`（命令超时） | BUSY(G45) 悬空/被拉死/错连 → 空闲应能读到低电平 |
| 换过一次仍 FAIL | 用万用表量 RST 复位脉冲、BUSY 电平变化；对照正式固件 `firmware/gun` 烧录后串口 `[radio] SX1262 ready` 是否出现 |

### T3 ESP-NOW FAIL 排查

| 现象 | 优先排查 |
| --- | --- |
| `code=-1/-3`（扫不到设备） | 对端是否上电并在信道 1；检测板每 1s 发心跳一定能被扫到；espnow-verify 需有流量才会发帧；两枪距离/天线朝向 |
| `code=-2`（扫到但无 ACK） | 目标 MAC 可能是路由器/手机等非 ESP-NOW 设备（旁路抓到但探测不应答）；把对端拉近重测 |
| 候选列表为空但有对端 | 对端被 AP 占用信道不在 1；或对端休眠（esp_wifi_set_ps 关掉） |
| 想重新测"扫描"分支 | 串口输入 `x` 清除已保存地址并重启 |

## 6. LED（G48）指示汇总

| 模式 | 含义 |
| --- | --- |
| 上电三闪（约 0.7s） | 代码已启动（不依赖串口） |
| 每秒闪 1 次（亮0.5s/灭0.5s） | T1+T2+T3 全部 PASS |
| 中速闪（亮260ms/灭260ms） | T2 LoRa PASS 但 T3 ESP-NOW FAIL |
| 快闪（亮120ms/灭120ms） | T2 LoRa 连接 FAIL |
| 常亮 / 常灭 | 程序未正常启动或 LED 通路异常（查 §5） |
